# Первый вклад в GitHub — через музыку

Цель: превратить авторскую работу в открытый, понятный и проверяемый материал. Календарь Contributions показывает опубликованные действия; он не заменяет качество результата.

## Маршрут одного задания

1. **Идея → Issue.** Записываем одну конкретную задачу, критерий готовности и исходники. Голосовая идея сама по себе не появляется на GitHub.
2. **Источники.** Автор передаёт аудио или заметки из Logic. Точные темп, размер, аккорды и такты подтверждаем по ним.
3. **Правка → отдельная ветка.** Меняем карточку трека и, когда есть экспорт, добавляем файл. Не заполняем неизвестное догадками.
4. **Pull request → просмотр.** Сравниваем исходник и новую версию. Автор утверждает смысл и подписи.
5. **Merge → результат.** После объединения в `main` материал доступен читателям; это и есть проверяемый вклад. Issue закрываем ссылкой на результат.

## Первое задание

[Issue #1 — музыкальный паспорт water glints](https://github.com/yogasnow/logic-recordings/issues/1): исходники получены 27.10.2026. В [папке произведения](tracks/03-water-glints/README.md) собраны MP3, полный паспорт, карта 64 тактов, рабочие ноты PDF/MusicXML, MIDI, код и ссылка на проект Logic в Release. Следующий этап — авторская слуховая и нотная проверка: расхождения между замыслом и текущей реализацией явно перечислены в паспорте.

«Змейка» на GitHub, если её подключить, рисует уже состоявшиеся Contributions. Она не отслеживает выполнение задач в реальном времени; для этого нужны Issues или Projects.
