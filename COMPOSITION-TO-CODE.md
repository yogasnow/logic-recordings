# От авторской мелодии к учебному коду

Этот маршрут соединяет два навыка: Снежана сочиняет музыку и записывает её нотами; затем переводит проверенные музыкальные решения в код. Код не подменяет авторскую партитуру и не выводит «точные ноты» из одного MP3.

## Один цикл работы

1. **Сочинить.** Записать мотив, размер, темп и хотя бы один законченный фрагмент в нотном стане или в Logic. Сохранить авторскую версию.
2. **Назвать партии.** Для каждого голоса отметить инструмент, диапазон тактов, высоты нот, длительности, паузы и динамику. Гармонию записать отдельно от мелодии.
3. **Экспортировать исходные данные.** Предпочтительны MIDI или MusicXML; PDF полезен для чтения и сверки. MP3/WAV нужен для слухового сравнения, но не заменяет нотный исходник.
4. **Выбрать язык под задачу.** TypeScript — для типизированных нотных событий и редактируемой аранжировки; JavaScript — для простого интерактивного прототипа; Python — для анализа, генерации аудио или обработки данных. Язык можно менять без изменения авторского замысла.
5. **Сделать первый маленький фрагмент.** Перенести 1–4 такта, проверить высоты, длительности и паузы по нотам, запустить код и прослушать результат. Лишь затем расширять работу.
6. **Сравнить версии.** Отделить авторскую партитуру, учебную кодовую аранжировку и финальный звуковой мастер. Записать, что в кодовой версии изменено намеренно, а что требует исправления.
7. **Поделиться результатом.** В одной папке хранить паспорт работы, ноты/MIDI или MusicXML, код, команду запуска и звуковой пример при наличии прав. Объяснить, какой следующий шаг может выполнить учащийся.

## Первая практика на TypeScript

[Инструмент `arrange.ts`](music-code/README.md) принимает нотные события и создаёт MIDI. В [шаблоне следующего произведения](templates/new-composition/README.md) есть поля для авторских данных. Запись вида `pitch: 60, start: 0, duration: 1` означает до первой октавы на одну четвертную долю — **только пример формата**, не нота существующей композиции.

Проверка понимания: сначала записать одну ноту на бумаге, затем занести её в `score.json`, предсказать длительность и высоту MIDI, запустить код и сравнить результат в нотном редакторе. Следующее упражнение — изменить **тембр**, не меняя нот, и объяснить разницу между композицией и аранжировкой.

## Что уже есть

- **Water Glints:** есть подтверждённые события, MIDI, MusicXML, ноты, аудио и код; на них проверена TypeScript-аранжировка.
- **Am Dialogue и Velvet and Sky:** есть аудио и пустые карточки ввода нот. Для точного кодового переноса нужны авторские MIDI/MusicXML, проект или проверенная запись нот.
- **Следующее произведение:** начинаем с авторского нотного фрагмента и сразу сохраняем его как часть учебного проекта. Никакой язык и никакая программа не назначаются автоматически до выбора конкретной задачи.
